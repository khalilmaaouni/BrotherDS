## BLOCK 1, FORECAST AND ESTIMATE ACCURACY

### 1.1 MAPE failure modes
- **Undefined at zero / blows up near zero**: MAPE = mean(|actual − forecast| / |actual|) × 100 is undefined when actual = 0, and small actuals produce huge percentages from tiny absolute errors (a 2-unit miss on an actual of 10 gives 20% MAPE; the same 2-unit miss on an actual of 1,000 gives 0.2%). Source (AGGREGATOR SOURCE, vendor doc but consistent with the academic finding below): https://wiki.wfmlabs.org/wiki/MAPE_WAPE_and_Forecast_Bias (opened 2026-08-16).
- **Asymmetry favoring under-forecast**: because the denominator is the actual, MAPE penalizes over-forecasts more than equivalent-magnitude under-forecasts (an over-forecast can produce unbounded percentage error while under-forecast error is capped near 100%). This is the core critique in the primary source below.
- **Primary source**: Hyndman, R.J. and Koehler, A.B. (2006), "Another look at measures of forecast accuracy," *International Journal of Forecasting* 22, 679 to 688, DOI 10.1016/j.ijforecast.2006.03.001. Opened at https://robjhyndman.com/publications/another-look-at-measures-of-forecast-accuracy/ (2026-08-16) and https://robjhyndman.com/papers/mase.pdf. The abstract states the methods used in the M-competition and M3-competition, and many previously-recommended measures, "are found to be degenerate in commonly occurring situations," and proposes **MASE (mean absolute scaled error)** as the standard cross-series measure. This is the canonical citation the product must implement against.

### 1.2 The metric decision table

| SITUATION | CORRECT METRIC | WHY (formula + citation) |
|---|---|---|
| Single series, no zeros, need business-readable % | MAPE, with caveats | MAPE = mean(\|Aₜ−Fₜ\|/\|Aₜ\|)×100. Only safe when actuals are bounded well away from zero and the audience needs a %. Undefined at 0, asymmetric (Hyndman & Koehler 2006, cited above). |
| Portfolio / aggregate reporting, mixed volumes | WAPE (a.k.a. WMAPE, MAD/Mean ratio) | WAPE = Σ\|Aₜ−Fₜ\| / Σ\|Aₜ\|. Volume-weighted, so high-volume items dominate correctly and it survives zero-actual periods in the mix. Baeldung explainer confirms formula and rationale: https://www.baeldung.com/cs/mape-vs-wape-vs-wmape (AGGREGATOR SOURCE, opened 2026-08-16). Still implicitly favors under-forecast at the aggregate because it is still a ratio to actuals. |
| Cross-series comparison, intermittent demand, need a scale-free measure | MASE | MASE = mean(\|Aₜ−Fₜ\|) / mean(\|Aₜ − Aₜ₋ₘ\|) [in-sample naive/seasonal-naive MAE in the denominator, m = season length]. Scale-free, defined even with zero actuals, benchmarked against a naive baseline by construction. Hyndman & Koehler (2006); extended for intermittent demand in Hyndman's "Another look at forecast-accuracy metrics for intermittent demand," https://robjhyndman.com/papers/foresight.pdf (opened 2026-08-16). |
| M5-style competition benchmarking across many series with different scales | RMSSE (root mean squared scaled error) | RMSSE = sqrt[ mean((Aₜ−Fₜ)²) / mean((Aₜ−Aₜ₋ₘ)²) ] over the in-sample naive squared error. This is the exact metric M5 used for its accuracy track; official description confirmed via https://www.sciencedirect.com/science/article/pii/S0169207021001874 (M5 accuracy competition paper, ScienceDirect, opened via search 2026-08-16). |
| Symmetric-looking % metric requested but MAPE's asymmetry is a known problem | sMAPE, but flag it, don't default to it | sMAPE = mean(2\|Aₜ−Fₜ\| / (\|Aₜ\|+\|Fₜ\|)) ×100. Intended to symmetrize MAPE but is **not actually symmetric**: because the forecast Fₜ is in the denominator too, sMAPE penalizes over-forecasts less and under-forecasts more (opposite-direction bias from MAPE), and can still blow up when Aₜ+Fₜ→0. Hyndman & Koehler (2006) documents this defect directly; it is why they proposed MASE instead. |
| Point loss function needs to match a business cost asymmetry (e.g., stockout costs more than overstock) | Pinball loss / quantile loss at the decision-relevant quantile τ | ρτ(u) = τ·u if u≥0, else (τ−1)·u, where u = actual − predicted quantile. For τ=0.5 it reduces to MAE. Minimized in expectation exactly at the true τ-quantile of the outcome distribution, the correct loss whenever a forecast is really a quantile commitment (safety stock, SLA). Formula confirmed at https://towardsdatascience.com/an-introduction-to-quantile-loss-a-k-a-the-pinball-loss-33cccac378a9/ (AGGREGATOR SOURCE, opened 2026-08-16), consistent with the standard quantile-regression literature (Koenker & Bassett). |
| Choosing between RMSE and MAE for a point forecast | RMSE punishes large errors disproportionately (squared loss ⇒ implies the forecast should be the conditional mean); MAE weights all errors linearly (implies the forecast should be the conditional median). Pick RMSE when large misses are disproportionately costly (e.g., stockouts cascading); pick MAE when the cost is roughly linear in the miss. | Standard decision-theory result: minimizing expected squared error is optimal iff loss is truly quadratic; minimizing expected absolute error is optimal iff the target is the median. |
| Reporting accuracy without a baseline | Always report accuracy **relative to naive or seasonal-naive** | An accuracy number with no baseline is meaningless, MASE/RMSSE build the baseline into the denominator for this reason. This is the direct implication of Hyndman & Koehler's critique and is also the design of M4/M5 (all submissions scored relative to a naive benchmark). |

### 1.3 What M4, M5, M6 actually established (numbers, with dates)
- **M4 (2018)**: statistical-ML "hybrid" methods (notably the winning "Exponential Smoothing + RNN" combination) beat pure ML and pure statistical methods; simple combinations of forecasts consistently beat individual sophisticated models, a headline replicated across the M-competition series. (General consensus finding; see M6 paper below for the lineage summary, NO-DATA on an exact numeric M4 error-reduction figure verified independently in this pass; flag as such rather than inventing one.)
- **M5 Accuracy (2022)**: Published in *International Journal of Forecasting* 38(4), pp.1346 to 1364. "All top 50 submissions outperformed the overall forecasting accuracy of the top-performing benchmark by more than 14%, with improvements higher than 20% for the top five performing teams and 22.4% for the winning team." M3/M4 improvements over benchmark were under 10% by comparison, meaning M5 saw roughly 2x the gain, driven by "complex global machine learning methods" (notably LightGBM-family gradient boosting) beating statistical benchmarks on **retail sales specifically**. Source: ScienceDirect abstract, https://www.sciencedirect.com/science/article/pii/S0169207021001874 (opened via search, 2026-08-16); cross-checked against the Columbia-hosted preprint PDF https://statmodeling.stat.columbia.edu/wp-content/uploads/2021/10/M5_accuracy_competition.pdf.
- **M5 Uncertainty (2022)**: a companion track scored quantile forecasts explicitly (pinball loss), separate paper: https://www.sciencedirect.com/science/article/pii/S0169207021001722 (found via search 2026-08-16, not separately opened, mark content above the title/existence as UNVERIFIED for exact numbers).
- **M6 (2024/2025)**: *"The M6 forecasting competition: Bridging the gap between forecasting and investment decisions,"* arXiv:2310.13357, published in *International Journal of Forecasting* 41(4) 1315 to 1354 (2025). Headline empirical finding: over the 48-week competition, **only 23.3% of teams beat the market benchmark on forecasting accuracy, only 28.8% built better portfolios than the benchmark, and only 6.7% did both**, i.e., the large majority of forecasting effort did not beat a naive/benchmark approach, mirroring the well-documented underperformance of actively-managed equity funds. Source opened: https://arxiv.org/abs/2310.13357 (2026-08-16).
- **Consolidated lesson for BrotherDS**: across M4/M5/M6 the single most robust empirical finding is that **a baseline (naive or seasonal-naive) is the null hypothesis every claim must beat**, and that in financial/noisy domains (M6) most sophisticated effort still fails to beat it. A BrotherDS claim with no stated baseline comparison is not verifiable in the sense these competitions define verification.

### 1.4 Aggregation traps
- Computing accuracy at the wrong grain hides item-level catastrophe: one industry example found **calculating MAPE on aggregated category data gave 3%, while calculating MAPE per-SKU and averaging gave 33%, a 10x difference from the same underlying data**, and a separate framing noted **30 to 40% MAPE is realistic at SKU level for long-tail items even though portfolio/aggregate MAPE can look far better**. Source (AGGREGATOR SOURCE, vendor practitioner content, but consistent with well-known cancellation-of-errors arithmetic, errors of opposite sign net out when summed before the % is taken): https://www.relexsolutions.com/resources/measuring-forecast-accuracy/ and https://izba.co/thought-leadership/mape-for-demand-forecasting (both opened via search 2026-08-16).
- The user's brief cites a **40% portfolio MAPE alongside 94.5% store-level MAPE** as a real anchor case. I could not independently verify that exact pair of numbers against a primary source in this pass (searches returned adjacent industry figures, 30 to 40% SKU-level MAPE, 3%-vs-33% aggregation gap, but not this specific 40%/94.5% pair). **NO-DATA on this specific figure**: treat it as the requester's own prior finding, not independently re-verified here, and do not restate it as externally sourced without that caveat.
- Mechanically, the trap is arithmetic: MAPE/WAPE computed on a sum-of-signed-errors basis lets over-forecasts on some items cancel under-forecasts on others, so a portfolio total can look accurate while every item is wrong in a different direction. This is a direct corollary of the Hyndman & Koehler critique (§1.1) applied to aggregation, not a separately-cited empirical claim.

## BLOCK 2, CAUSAL CLAIMS IN COMMERCIAL SETTINGS

| DESIGN | WHAT IT LICENSES YOU TO CLAIM | THE ASSUMPTION TO TEST |
|---|---|---|
| Randomized holdout / geo experiment / switchback | A causal average treatment effect of the specific intervention, at the randomization unit, over the study window, the gold standard. | Randomization actually balanced units (SRM / balance check on pre-period covariates); no interference/contamination across arms (SUTVA). |
| Difference-in-differences | Causal effect of treatment under the counterfactual that treated units would have moved in parallel with controls absent treatment. | Parallel pre-trends. Standard test: event-study regression showing pre-treatment period coefficients ≈ 0. Caveat found in current literature: pre-testing on pre-trends itself has low power and can bias inference, recent papers (2023 to 2025, e.g. arXiv:2310.15796, arXiv:2510.26470, opened via search 2026-08-16) recommend equivalence-testing frameworks rather than a simple significance test of pre-trends. |
| Synthetic control | Causal effect for a single (or few) treated unit(s) versus a data-driven weighted combination of untreated donors. | Good pre-treatment fit (low pre-period RMSPE) and a donor pool free of spillover; tested via **placebo-in-space** (reassign "treatment" to each donor, compare post/pre MSPE ratios) and **placebo-in-time** (fake treatment date). Abadie et al.'s original method; summary confirmed at https://bookdown.org/mike/data_analysis/sec-synthetic-control.html and the AEA methods note https://www.aeaweb.org/content/file?id=12409 (opened via search 2026-08-16). |
| Event study | Dynamic treatment-effect path around a known event date, and a visual/statistical pre-trend check for other designs. | No confounding events coincide with the study event; flat pre-period estimates. |
| Regression discontinuity | Local causal effect right at a threshold/cutoff, nothing about effects away from the cutoff. | No manipulation/bunching at the cutoff. Standard test: **McCrary density test** (density of the running variable must be continuous at the cutoff). Confirmed via https://ifs.org.uk/sites/default/files/output_url_files/CWP501818.pdf and bookdown RDD chapter (opened via search 2026-08-16); note a 2020 arXiv paper (2009.07551) shows continuous density is neither necessary nor sufficient in general, treat the McCrary test as a red flag, not a proof. |
| Instrumental variables | Local average treatment effect for "compliers", units whose treatment status the instrument actually moves. | Relevance (instrument correlates with treatment, test via first-stage F-statistic / weak-instrument test) and the exclusion restriction (instrument affects the outcome ONLY through treatment, **not testable** in exactly-identified models; this is an assumption you argue, not one you can confirm from data). Confirmed via https://pmc.ncbi.nlm.nih.gov/articles/PMC6096851/ (falsification-strategy review, opened via search 2026-08-16). |
| Uplift modeling | Which units respond most to treatment (heterogeneous treatment effect ranking), evaluated via Qini/uplift curves, NOT population-average causal effect by itself; still requires an underlying randomized or quasi-randomized source of treatment variation to be causal at all. | Same identification assumptions as whatever design generated the treatment/control labels feeding the uplift model (usually an RCT), uplift modeling is an estimand/targeting layer on top of a design, not its own identification strategy. NO-DATA found for a single canonical uplift-modeling citation in this pass beyond the general causal-ML literature (EconML/causalml docs); do not overstate a specific paper as "the" uplift reference. |
| Bayesian structural time series (CausalImpact) | Counterfactual "what would this metric have done without the intervention" for a single treated series, using a fitted state-space model on correlated control series/covariates. | Control series must be unaffected by treatment and predictive of the treated series pre-intervention; a good pre-period fit is required before trusting the post-period counterfactual. Brodersen et al., Google's CausalImpact; package actively maintained, R package v1.4.1 released 2025-09-26 per CRAN, confirmed via search 2026-08-16 (https://packages.oit.ncsu.edu/cran/web/packages/CausalImpact/index.html). |

### What observational sales data genuinely cannot establish
Observational (non-experimental) sales data cannot, by itself, distinguish correlation from causation for any intervention that was not randomly assigned, confounders (seasonality, competitor actions, macro shocks, self-selection into promotion) can produce any observed association. The canonical grounding for "association is not causation without an identification strategy" is the Rubin causal model / potential-outcomes framework; DiD, synthetic control, RDD, and IV are all attempts to approximate a randomized comparison from observational data under a stated, falsifiable-in-part assumption, none of them removes the need to state and test that assumption. This is standard content across the sources cited in the table above (Columbia IV review PMC6096851; DiD/RDD/synthetic-control chapters at bookdown.org/mike/data_analysis, opened via search 2026-08-16); I did not find a single textbook citation more canonical than Rubin (1974)/Imbens & Rubin worth asserting further without opening a primary copy, flagged as **partially UNVERIFIED at the textbook-citation level**, methodology-level claims are well supported by the sources above.

### Power and minimum detectable effect (worked formula)
For a two-proportion test (e.g., promo lift on conversion rate):

**MDE = (z_(1−α/2) + z_(1−β)) × √(2·p̄·(1−p̄)/n)**

where p̄ is the pooled/baseline rate, n is the per-arm sample size, z_(1−α/2) ≈ 1.96 at α=0.05 two-sided, z_(1−β) ≈ 0.84 at 80% power. Rule of thumb: to detect a relative lift of x% on a baseline rate p with 80% power / 95% confidence, required per-arm n ≈ 16·p·(1−p)/(x·p)² (a standard simplification of the formula above). Source: https://mbrenndoerfer.com/writing/sample-size-minimum-detectable-effect-power-analysis-mde-underpowered-studies and X/Twitter engineering blog on A/B test power sizing, https://blog.x.com/engineering/en_us/a/2016/power-minimal-detectable-effect-and-bucket-size-estimation-in-ab-tests (both AGGREGATOR SOURCE / vendor engineering blogs, opened via search 2026-08-16, but the formula itself is the standard two-proportion z-test power formula found in any intro-stats reference).

### Detail behind the table

**Structured expert elicitation protocols compared**:
- **Cooke's classical model**: performance-weighted, requires 5 to 10 experts and a calibration/seed-question set with known true answers; weight = f(statistical accuracy via chi-square p-value, informativeness). https://www.journals.uchicago.edu/doi/full/10.1093/reep/rex022 (opened 2026-08-16).
- **SHELF (Sheffield Elicitation Framework)**: a facilitator-led *behavioral aggregation* protocol (group discusses to a consensus distribution, not weighted individual estimates); includes the "roulette method" (chip-allocation histogram) and quartile-elicitation techniques. Official site: https://shelf.sites.sheffield.ac.uk/ (opened via search 2026-08-16).
- **IDEA protocol** (Hemming, Burgman et al. 2018, *Methods in Ecology and Evolution*): "Investigate, Discuss, Estimate, Aggregate", individual private estimate first, then anonymized group discussion, then re-estimate, then mathematically aggregate. Explicitly designed to counter groupthink and dominant-expert bias by anonymizing the discussion phase. https://besjournals.onlinelibrary.wiley.com/doi/full/10.1111/2041-210X.12857 (opened via search 2026-08-16).
- **Delphi (classic)**: iterative anonymous rounds with statistical feedback between rounds; known failure modes are low response rates in later rounds (worse with larger panels and more items), high dropout, no standardized consensus threshold, and low replicability, sensitive to exactly who the panelists are. Source: https://www.ncbi.nlm.nih.gov/pmc/articles/PMC6438267/ and related PMC sources (opened via search 2026-08-16).
- **Does expert weighting beat equal weighting?** Evidence favors yes for Cooke's performance-weighting specifically (32/33 studies in-sample per the cross-validation paper above), but this is a narrow empirical base (one method family, in-sample), do not generalize to "any weighting beats equal weighting" without qualification.

**Calibration of human judgment**:
- **Brier score** = mean((forecast probability − outcome)²) over binary-outcome forecasts; a **strictly proper scoring rule**, expected score is uniquely maximized by reporting true calibrated probabilities, not by hedging or overstating confidence. Gneiting & Raftery (2007) formalized strict propriety; Tetlock's superforecasters study found top forecasters beat average Brier scores by roughly 60% and did not regress to the mean over years of competition. Source: search-aggregated from multiple academic summaries including https://www.cambridge.org/core/journals/judgment-and-decision-making/article/weighted-brier-score-decompositions-for-topically-heterogenous-forecasting-tournaments/ (opened via search 2026-08-16), Tetlock's own book (*Superforecasting*, 2015) is the primary source for the 60%/no-regression claim and was **not independently re-opened in this pass**; treat that specific figure as UNVERIFIED-secondhand until the book or IARPA ACE-tournament paper is opened directly.
- **Reference-class forecasting / the outside view** (Flyvbjerg): correcting a single project's inside-view estimate by anchoring it to the empirical distribution of outcomes for a reference class of similar past projects; endorsed by the American Planning Association in 2005. Root cause targeted: **optimism bias and strategic misrepresentation** (Flyvbjerg et al. 2004) as the twin drivers of megaproject overruns. Source: https://www.sciencedirect.com/science/article/pii/S2666721523000248 and https://www.tandfonline.com/doi/full/10.1080/09537287.2025.2578708 (opened via search 2026-08-16).

**Third-party data appraisal standards**:
- **Datasheets for Datasets** (Gebru et al.): a standardized documentation questionnaire (motivation, composition, collection process, uses, distribution, maintenance) attached to a dataset before it's trusted.
- **Croissant**: MLCommons/Google-led JSON-LD metadata format for ML-ready datasets, adopted by Kaggle, Hugging Face, and OpenML; NeurIPS 2024 Datasets & Benchmarks paper, https://arxiv.org/html/2403.19546v2 (opened via search 2026-08-16).
- **ISO 8000 / DAMA-DMBOK**: ISO 8000 is a real, active ISO standard family for data quality (master/transactional data, cross-organization exchange). DAMA-DMBOK's canonical six data-quality dimensions are **accuracy, completeness, consistency, timeliness, uniqueness, validity**. Source (AGGREGATOR SOURCE for the synthesis, but ISO 8000 and DAMA-DMBOK are both real, verifiable standards bodies/publications): https://quality.arc42.org/standards/iso-8000 and https://dataworkers.io/resources/data-quality-dimensions/ (opened via search 2026-08-16).
- **Known biases in commercial panel/syndicated data**: coverage gaps at specific major retailers (named above), projection-factor uncertainty, and the specific finding that bias, not sampling error, dominates total error in panels large enough to be useful, meaning **bigger panels do not fix this class of error**. Source as above, cpgdatainsights.com (AGGREGATOR SOURCE, industry practitioner site, opened via search 2026-08-16).

**Assumptions, sensitivity analysis correctly done**:
- One-at-a-time (tornado diagram) is cheap and interpretable but **misses interaction effects between assumptions**, two assumptions each individually harmless can combine to flip a decision, and OAT will not show this.
- **Morris screening**: N·(P+1) model runs, ranks parameters by mean and variance of elementary effects; a validated cheap proxy for Sobol total-effect index (S_T), per https://link.springer.com/article/10.1007/s00158-018-2071-7 (opened via search 2026-08-16).
- **Sobol indices**: full variance-based decomposition, N·(P+2) runs via Saltelli's estimator, gives first-order and total-effect sensitivity including interactions, the gold standard but expensive; the pragmatic two-stage practice is Morris to screen, Sobol to refine the shortlist.
- **When Monte Carlo over the full assumption set is warranted**: when Morris/Sobol screening shows two or more assumptions with material total-effect indices that interact (S_T noticeably exceeds first-order Sᵢ), a full joint Monte Carlo over the correlated assumption space is needed rather than trusting per-assumption tornado ranges independently.
- Standard reference: Saltelli et al., *Global Sensitivity Analysis: The Primer*, https://www.academia.edu/22792080/Global_Sensitivity_Analysis_The_Primer (opened via search 2026-08-16).

**Hypotheses, pre-registration, what it buys and doesn't**:
- **What it buys**: a timestamped, public commitment to the primary hypothesis, metric, and analysis method before the outcome is known, which (a) prevents HARKing (Hypothesizing After the Results are Known) on the primary claim, and (b) makes deviations visible if anyone checks.
- **What it explicitly does NOT buy**, per OSF's own preregistration page (opened directly, 2026-08-16, https://www.cos.io/initiatives/prereg): it does **not** prevent exploratory analysis after the fact, does not eliminate the need to interpret results honestly, and does not itself verify that the executed analysis matches the registered plan, responsibility for reporting deviations rests on the researcher via a "Transparent Changes document," not on any automated check. This directly confirms the premise stated in the brief (see Block 4).
- **Registered Reports**: a stronger variant where the study design/analysis plan is peer-reviewed and accepted for publication *before* data collection, removing the incentive to selectively report significant results, named in the brief, real and current, but not independently re-opened as a primary source in this pass (NO-DATA beyond the general description above).
- **Canonical severity citations**: Simmons, Nelson & Simonsohn (2011), up to 60% false-positive inflation from undisclosed flexibility, opened directly above. Gelman & Loken (2013), garden of forking paths, opened directly above. Ioannidis (2005) "Why Most Published Research Findings Are False", named per brief, **NO-DATA**, not independently opened in this pass; do not assert specific numeric claims from it without re-verification.

## BLOCK 4, VERIFYING THAT EXECUTION MATCHED THE PLAN

**Verdict: this is genuinely unclaimed territory for general observational/business analytics, but a partial, narrower version of it exists in regulated clinical research, and specification-curve/multiverse analysis is the closest general-purpose technical tool.**

1. **OSF preregistration confirmed to not do this.** Fetched directly (2026-08-16) from https://www.cos.io/initiatives/prereg: preregistration relies on "researcher transparency and community accountability," not an automated or systematic verification mechanism. Any deviation disclosure is voluntary, via a "Transparent Changes document," not mechanically checked against the registered plan.

2. **The closest real analogue is clinical-trial protocol-deviation tracking.** FDA guidance (https://www.fda.gov/media/184745/download, "Protocol Deviations for Clinical Investigations," opened via search 2026-08-16) formally defines a **protocol deviation** as any noncompliance with the trial protocol or Good Clinical Practice, requires sponsors to report deviations against the pre-specified Statistical Analysis Plan (SAP), and requires **Per-Protocol sensitivity analyses** specifically to test whether deviations changed the result. This is process-and-documentation verification (site monitors, audit trails, deviation logs cross-referenced to the SAP), not an automated diff between a registered analysis script and the executed one. It is real, mandated, and auditable, but it is manual/procedural, not mechanical.

3. **What a mechanical diff would have to compare, if it existed** (synthesized from the above, not itself a cited existing tool):
   - The registered **primary metric/estimand** vs. the metric actually reported as primary in the write-up.
   - The registered **model/test specification** (e.g., "two-sided t-test, α=0.05, on log-transformed revenue") vs. the actual code/model that ran.
   - The registered **sample/inclusion criteria** vs. the actual filter conditions applied to the data (row-count and filter-predicate diff).
   - The registered **covariates/controls** vs. the covariates actually included in the final model.
   - Any **post-hoc exclusions** (outlier removal, date-range trims) not present in the registered plan.
   - This is exactly the surface that **specification curve analysis / multiverse analysis** (Simonsohn, Simmons & Nelson's "specification curve," and the broader multiverse-analysis literature) makes visible, but as a *disclosure* tool run by the researcher, not as an independent, adversarial check that something claimed as "the pre-registered analysis" is in fact what ran. Source: https://masurp.github.io/specr/ and https://www.psychologicalscience.org/observer/run-all-the-models-dealing-with-data-analytic-flexibility (opened via search 2026-08-16, both AGGREGATOR/explainer-level but pointing to the real primary technique).

4. **Detecting undisclosed analytic flexibility after the fact, literature exists, but it's statistical inference about a distribution of results, not a mechanical single-study diff.** Simmons/Nelson/Simonsohn and Gelman/Loken (Block 3) establish the *mechanism* by which undisclosed flexibility inflates false positives, including with zero intent to deceive; p-curve analysis (Simonsohn et al., a related but separate technique) attempts to detect selective reporting from the *distribution* of p-values across a literature, not from a single study's registered-vs-executed comparison. I found **no tool, standard, or paper that performs a mechanical diff between a specific registered plan and a specific executed analysis run** for general business/observational analytics, this appears to be the gap the brief's prior research correctly identified. The nearest thing that exists is procedural (clinical trial deviation logs against a SAP, human-audited) or statistical-population-level (p-curve, specification curves), not a single-claim mechanical verifier.

The consistent pattern across all five real-world/enterprise-grade benchmarks (as opposed to toy/academic ones like Spider 1.0) is **large accuracy gaps versus human baselines and versus toy-benchmark performance**: Spider 1.0's 86.6% collapses to Spider 2.0's 6%; BIRD's human 93% vs. GPT-4-alone 55%; DABStep/DSBench/MLE-bench all sit in the 12 to 35% range on realistic multi-step tasks.

### Documented failure modes on statistics/arithmetic, and whether tool use fixes it
- LLMs "approximate arithmetic rather than executing it accurately," and accuracy degrades further when computation is embedded in a word problem rather than isolated. Source: search-aggregated academic summary, https://arxiv.org/html/2502.08680v1 (opened via search 2026-08-16).
- **Tool use / code execution measurably reduces (not eliminates) computation errors**: one study found tool-augmented reasoning reduced computation errors from 439 to 181 across Gemini 2.5, GPT-4o-mini, Claude Sonnet, and DeepSeek R1 on the same task set; MathChat-style conversational tool use improved accuracy by roughly 6 percentage points, reaching 60% on half the tested categories. Source: aggregated academic search results, arXiv papers referenced via search (2026-08-16), figures reported as found, not independently re-derived.
- **Important caveat found in the same search**: "Tool-Induced Myopia", even with correct tool use, LLMs can substitute computation for reasoning, producing fewer arithmetic errors but *more* logical/assumption errors. This means tool use shifts the failure mode rather than eliminating unreliability; verification still needs to check the *setup* of the calculation (assumptions, formula choice), not just whether the arithmetic itself was executed by a calculator/interpreter.

### LLM-as-judge: measured agreement and biases
- GPT-4-as-judge reportedly reaches **>80% agreement with human evaluators**, comparable to **81% human-human agreement**, meaning LLM judges can match human-level *inter-rater* agreement, not that they are error-free against ground truth.
- **Position bias**: up to a **75% preference for the first-positioned response** in pairwise comparisons in the studies found.
- **Verbosity bias**: systematic preference for longer responses independent of quality.
- **Self-preference / self-enhancement bias**: **10 to 25% preference** for the judge model's own outputs over other models' outputs of equal quality.
- Source: aggregated from search results including https://arxiv.org/pdf/2410.21819 (Self-Preference Bias in LLM-as-a-Judge) and the LLM-judge-bias survey site https://llm-judge-bias.github.io/ (opened via search 2026-08-16). These specific percentages come from a search-synthesized summary rather than a single primary paper opened directly in this pass, **treat the exact percentages (75%, 10 to 25%, >80%) as UNVERIFIED pending a direct open of the underlying paper(s)**, though the *direction and existence* of all three biases is well-attested across multiple independent papers found in the search.

### The defensible rule for when an LLM may sit in a verification path
An LLM **may** sit in a verification path only as a *first-pass triage/flagging* layer whose output is itself checked by a deterministic re-run or a human before any claim is marked verified, e.g., flagging candidate deviations between a registered plan and executed code for a human/deterministic-diff tool to confirm, or drafting a calibration question set for a human expert to answer. An LLM **may not** sit in a verification path as the final arbiter of (a) any arithmetic or statistical result that a deterministic calculation could check directly, (b) whether an executed analysis matches a registered plan (this needs a mechanical diff, not a semantic judgment prone to position/verbosity/self-preference bias), or (c) whether a claim clears its stated uncertainty band, since the benchmarks above show 6 to 35% task-level reliability on exactly this class of multi-step analytical work even before judge-specific biases are added on top. This rule is consistent with the user's own global CLAUDE.md instruction that "a class that costs more in re-work than it saves twice in a row leaves the lane" and that verification is never delegated to the cheap/LLM lane.

## THREE FINDINGS THAT SHOULD CHANGE THE PRODUCT DESIGN

1. **No accuracy claim is meaningful without a stated baseline and a stated grain.** Hyndman & Koehler (2006) and the M4/M5/M6 lineage all build the baseline into the metric itself (MASE/RMSSE scale against naive/seasonal-naive); the aggregation-trap evidence (§1.4) shows a portfolio-level number can look fine while hiding item-level catastrophe purely from sign-cancellation. **BrotherDS should refuse to accept a "verified" claim that doesn't declare both its grain (SKU/store/portfolio) and its baseline.**

2. **The five non-system origins need five different, named discount mechanisms, not one generic "confidence score."** Vendor data needs a coverage/bias discount that does NOT shrink with more data (bias, not sampling error, dominates per the panel-data literature); expert input needs Cooke-style calibration-based weighting (32/33 studies favor it over equal weighting); assumptions need OAT-then-Morris-then-Sobol escalation, not a single sensitivity pass; hypotheses need pre-registration plus explicit deviation disclosure, discounted hard on any undisclosed forking-path exposure regardless of the p-value. A single blended "trust score" across these origins would hide exactly the failure modes each literature identifies separately.

3. **Plan-vs-execution verification is a genuine product opportunity, not a solved problem to route around.** OSF explicitly does not do this (confirmed directly from cos.io). The only real precedent, clinical-trial SAP-vs-protocol-deviation tracking, is manual/procedural, and the closest technical tool (specification-curve/multiverse analysis) is a self-disclosure aid, not an adversarial mechanical diff. A mechanical diff comparing registered primary metric, model spec, inclusion criteria, covariates, and exclusions against the executed run is unclaimed territory BrotherDS could own, but building it as an LLM-judged step would be a mistake given Block 5's findings (12 to 35% task reliability, plus judge-specific biases); it should be built as a deterministic structural diff over a declared analysis manifest, with an LLM only as a flagging layer feeding that diff.
